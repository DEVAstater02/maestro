# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Maestro is a voice-first AI tutoring application. Users go through a **curation phase** (voice interview to assess knowledge/goals → generates a syllabus) followed by a **learning phase** (real-time voice interaction with a tutor LLM, Socratic method, auto-generated Mermaid visualizations).

## Commands

### Backend (FastAPI, root of repo)
```bash
pip install -r requirements.txt
uvicorn app.main:app --reload   # runs on localhost:8000
```

### Frontend (Next.js, `frontend/` directory)
```bash
cd frontend
npm install
npm run dev     # runs on localhost:3000
npm run build

```

### Database
- MySQL 8.0+ required
- Apply schema manually: `tables.sql` + any files in `migrations/`
- No ORM auto-creation; all DDL is manual

## Architecture

### Data Flow
```
Browser ←→ WebSocket ←→ FastAPI ←→ LLM (Claude/OpenAI/Gemini/Grok)
                           ↓
                    STT → TTS → Visualizer → MySQL
```

### Backend Layer Structure (`app/`)

| Layer | Path | Role |
|-------|------|------|
| Routers | `app/routers/` | HTTP endpoints for auth, syllabus CRUD |
| WebSocket handlers | `app/main.py` | `/ws/curation` and `/ws/voice` entrypoints |
| Services | `app/services/` | Orchestration: STT, TTS, LLM, Curation, Visualization |
| Repositories | `app/repositories/` | Provider implementations (Claude, Gemini, OpenAI, Grok, Cartesia, ElevenLabs, AssemblyAI, MySQL) |
| Prompts | `app/prompts/` | System prompts for tutor, visualizer, curation, session memory |
| Models | `app/models/` | Pydantic request models + DB dataclasses |
| Utils | `app/utils/` | JWT + auth helpers |

### Two WebSocket Flows

**`/ws/curation`** — onboarding interview:
1. Receives topic/subject/persona from client
2. Conducts multi-turn voice interview via LLM
3. Detects `<conclude_curation>` tag → generates JSON syllabus
4. Persists syllabus to MySQL, sends UUID back to client

**`/ws/voice`** — learning session:
1. Client sends `syllabus_id` to join/resume session
2. Each turn: user audio → STT transcription → LLM response → TTS audio chunks streamed back
3. Visualizer runs a **parallel LLM call** to generate a Mermaid diagram for the topic
4. Session memory condensed via LLM every 10 turns (keeps last 5 in-memory; older turns persisted to DB)

### LLM Abstraction
All LLM providers implement `generate_response()`, `stream_response()`, and optionally `generate_structured_response()`. Selected at startup via `LLM_PROVIDER` env var. Claude uses AsyncAnthropic with ephemeral prompt caching.

### TTS Streaming Strategy
LLM streams text → sentence-buffered → TTS called per sentence → audio chunks streamed over WebSocket. Cartesia uses sentence-boundary buffering; OpenAI/ElevenLabs stream directly. Returns `(text_chunk, audio_bytes)` tuples.

### Visualizer
Parallel LLM call generates `VisualisationResponse` (Pydantic): `{ title, diagram (Mermaid), explanation, keyPoints, examples }`. Output is sanitized to fix common Mermaid syntax errors before sending to client as `{ "type": "visualisation", "format": "structured", "data": {...} }`.

### Frontend (`frontend/`)
- `/` — Auth or Dashboard (syllabus list + start curation)
- `/learn/[id]` — Learning interface for a syllabus
- `audioPlayback.ts` — Handles MP3/PCM/raw WAV format detection for streaming audio
- Visualization components support Mermaid, NetworkGraph, DataChart, AgentFlow

## Key Constraints

**Voice-first output**: All LLM responses must be speech-friendly — no markdown, asterisks, or special characters. Responses are 2–4 sentences / 40–60 words with contractions and natural phrasing.

**Session memory**: Conversation history stored as a JSON blob in `conversations` table. In-memory, only the last 5 messages are kept; older messages are persisted and a condensed `session_memory` string (generated by LLM) replaces them every 10 turns.

**Provider flexibility**: LLM/STT/TTS providers are loaded lazily and can be swapped via env vars without code changes. Add new providers by implementing the corresponding abstract interface in `app/repositories/`.
